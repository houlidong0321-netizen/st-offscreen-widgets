## 安装

酒馆 → 扩展面板 → **Install extension** → 粘贴：

```
https://github.com/houlidong0321-netizen/st-offscreen-widgets
```

安装后刷新页面。入口在**输入框旁边的「魔法棒」菜单**里，叫「Ego 小助手」。顶部扩展面板里没有入口，这是刻意的。

> **建议用 Git 地址安装**。手动解压复制的话，酒馆侧没有 Git 仓库信息，扩展内的「检查更新」会用不了。

界面有 7 个标签页：

## 组件生成

用来生成正文之外的附加内容。整个面板就是预览区，**组件列表收在右上角按钮里**（列表不用天天调，不占地方）。

### 新建组件

点「组件列表 → 新建组件」，两种方式：

- **自行输入** — 填名称和提示词
- **从预设提取** — 穿梭框：左上角选酒馆预设 → 左列表勾条目 → 点 **→** 移到右侧 → 填名称 → 确认

预设条目会作为附加设定随组件一起发送。

### 生成与查看

- **生成全部组件** — 跑所有已启用的组件
- 每个组件也能在列表里单独生成（▶ 按钮）
- 结果是独立 iframe 渲染，内容超出时**在预览框内部滚动**，功能栏始终留在框顶
- 每个预览有：☆收藏 / ⛶全屏 / 🗑删除结果 / 源码 / 重新生成
- 左上角箭头可折叠，**折叠状态会记住**（下次打开保持原样）

### 一个重要设计

组件的系统提示词带**最高优先级指令**：忽略预设条目里自带的固定输出格式（那些是给正文用的排版规范），只提取其中的设定信息，HTML 排版由模型自主决定。所以从预设提取条目不会把正文的格式要求带进来。

## 表格生成

维护六张跨轮次累积的状态表。

**内置表格**：日程表、角色表、场景表、物品轨迹表、核心待办事项表、伏笔表。

### 表格管理（右上角）

- 每张表有**独立开关**：开＝生成并把规则写进提示词；关＝不生成、不显示、提示词也不含它
- 可改表名、改列（`英文字段名:中文列名`，每行一个）、编辑该表的规则说明
- 可上下排序、新建自定义表、恢复默认六表

**提示词随配置自动变化** —— 新建一张表就自动多一段规则和一个 JSON 键，不用改代码。

### 规则要点

提示词里写死了这几条：

- **「正文触发原则」只约束场景表与物品轨迹表** — 正文没写就原样保留旧数据，禁止靠推理主动改动
- **角色表明确豁免** — 可以描写不在场角色此刻的状态
- **各表清理规则彼此独立** — 场景表有 10 章失活清理、伏笔表回收后下轮删除、待办事项一旦开始发生即整行删除、物品轨迹表按纪念/杠杆两类分别判定终态
- **增量维护不是重写** — 每次会把已有表格完整发过去，要求保留每一行，只改真正变化的字段

### 生成方式

面板可直接手动生成。自动模式在设置里配（见下方[设置详解](#表格)）。

单元格可直接点击编辑，每张表下方有「+ 添加一行」。

## 剧情推演

预演未来剧情走向，省得不知道该写什么。

### 发展方向（右上角）

内置九个：HE / BE / 狗血 / 虐心 / 日常 / 宫斗 / 商战 / 豪门 / 励志。

**每个方向不只是标签，还带一段写作约束**（「可以写 / 不可以写」），会原样写进提示词。比如：

- 「日常」允许写"因为一顿饭的一句话彻底吵翻"，禁止写日程流水账
- 「狗血」允许身世秘密、旧情人回归，禁止穿越重生这类改变世界规则的设定
- 「商战」禁止编造具体财务数字当既定事实

可自行编辑、增删、恢复默认。

### 自定义事件（右上角）

**想到什么写什么** —— 完整事件、半个点子、某句台词、某个画面、想看到的结果，甚至只是"我想让他们吵一架"。

模型会自行判断落点：能成篇的做事件、是走向的做分支、太零碎的补全成情节塞进戏剧核心或导火索、指定了结果的让某条分支导向它。这里写的内容**必须**体现在矩阵里。

### 生成

点「生成推演」会先弹确认框，显示当前方向和自定义条数，并让你选：

- **重新生成** — 不发送现有矩阵，进度清零
- **续写** — 发送现有矩阵与当前进度，以当前事件为起点往后写

生成前会自动备份上一版矩阵（最多 3 版），主界面有「**恢复上一版**」，而且可以来回切换。

### 事件与分支的规则

- **事件是宏观篇章，不是单个回合**。"吃饭"不是事件，"因为吃饭吵翻""吃饭时弄丢关键物品"才是
- **分支是事件的结局走向**，不是用户的具体动作，也不写情绪描写。例如：

  ```
  [事件01] 撞见对方在酒吧喝多了
    结果A：带回了家   → [事件02]
    结果B：没有带回家 → [事件03]
  ```

- **分支不限 2 条**（2-4 条按需），必须穷尽覆盖所有合理走向
- 禁止写穿着、表情、语气、情绪形容 —— 那些是正文该写的
- 导火索和过程可以慢慢铺垫，**分支只在最终结果落定的那一轮才触发**

### 自动推进

当前事件与分支会注入聊天，同时要求模型在事件真正结束时于正文末尾输出一个隐藏标记（HTML 注释，你看不见）：

```
<!--EGO_PLOT:01:A-->
```

扩展扫到后自动：置灰未走的分支 → 记录路径 → 推进到分支指向的事件 → 把注入内容换成新事件。

**兜底**：模型没输出标记时，每条分支旁有「走这条」手动推进；每个事件有 ✏️ 可编辑（改代号/核心/导火索/分支指向）；顶部可「重置进度」。

### 关于结局

一次生成是故事的**一个阶段**，不是完结。每条线最终收束到**阶段性开放结局**（`OPEN`）—— 告一段落但故事仍在继续。只有勾选 HE 或 BE 时才允许生成最终结局（`END`）。

写入前会自动校验：指向不存在编号的悬空分支自动改为 `OPEN`；发现走不到结局的死循环会点名提示。

## 总结

把各章现成摘要按场景编排成剧情档案。

### 两种生成方式

| 方式 | 用的是 | 什么时候用 |
|---|---|---|
| **大总结（扩展）** | 扩展配置的 API | 常规用法 |
| **大总结（发到聊天）** | **酒馆的预设** | 扩展这边效果不好时换这个 |

「发到聊天」会把提示词发进当前聊天，回复里出现 `<大总结(...)>…</大总结(...)>` 时**自动捕获并存档**。等待期间面板顶部有提示，可随时取消。

### 输出内容

按转场分区间，每个区间包含：

- **高光对话** — 逐字原文摘抄，一行 = 一句台词 + 一个短动作（40 字内），只取 3-5 行
- **不可忽略物理因素** — 信物、伤口等，写清来源与当前位置
- **线性摘要搬运记录** — 各章现成摘要，带 `[Chapter_X]` 标签与锚点关联

场景/物品标签会复用表格模块里已有的 `[Scene_X]` / `[Item_Anchor_X]`，这样物品表和总结的锚点能对上 —— 回忆某个物品时能带回当时的场景与对话。

### 计数方式（重要）

设置里可选：

- **按楼层**（默认）— 用酒馆消息 ID 计数，**包含已隐藏的楼层**。隐藏旧楼层不会影响进度
- **按章节标签** — 识别正文里的 `[Chapter_X]`

> 如果你习惯总结完就隐藏旧楼层，**务必用「按楼层」**。

### 压缩

- **手动** — 每条总结卡片上有「压缩」按钮
- **自动** — 滑窗差值：设 5 ＝ 出现第 5 次总结时压缩第 1 次，第 6 次时压缩第 2 次

**压缩只动叙述部分**，高光对话与物理锚点一字不改。原文一直保留，点「还原」可无损回到未压缩状态。

### 其他功能

- **重新生成** — 章号范围不变，覆盖原内容（你审核不过就点它）
- **导入大总结** — 粘贴你以前写好的整份总结，填起止范围即可。标题里写了"第1-20章"会自动填好输入框
- **隐藏楼层** — 手动指定区间，走酒馆自带的 `/hide` `/unhide`，与斜杠命令效果完全一致。楼层号即消息 ID（从 0 开始）。有已隐藏记录列表可逐条恢复

## 设定

只属于**当前聊天**的设定。存在聊天存档里，换聊天、换角色都看不到，也不会写进角色卡世界书污染其它聊天。

四个分类：**世界设定 / NPC / 用户人设 / 其他**，注入时按分类分组。

每个条目可配：

- **关键词** — 留空＝常驻注入；填了（逗号分隔）＝最近若干层聊天里出现该词才注入（省 token）
- **注入深度** — 每条独立设置，数字越小越靠近最新消息
- **启用开关**

## 收藏夹

组件预览右上角点 ☆ 即可收藏，选择（或新建）文件夹。

- 按文件夹分组，每条标注**日期时间、角色名、用户名**
- 点 👁 就地展开渲染预览，也能全屏
- 支持新建/重命名/删除文件夹、移动收藏、删除收藏
- **全局保存**，跨聊天可见。存的是生成时的 HTML 快照，组件后来重新生成不影响已收藏的内容
- 重新生成后 ☆ 会变回空心，表示当前这版还没收藏

> ⚠️ 收藏存在全局设置里，收藏大量长内容会让设置文件变大，建议定期清理。

## 设置详解

设置页按模块分组，**默认全部折叠**（除 API），点标题展开。

### API 预设

维护多套 API，各模块在自己的分组里选择用哪套。

- 每套预设：名称 / URL / Key / 模型
- **测试连接** — 发一条最小请求当场验证，不用等生成时才发现问题
- **拉取模型** — 从 `/models` 拉列表
- **流式请求** — 默认关闭。某些服务只支持流式时再开
- URL 填到 `/v1` 即可，扩展会自动补 `/chat/completions`

> ⚠️ **浏览器直连第三方 API 常被 CORS 拦截**。OpenAI 这类官方接口不允许浏览器直连（酒馆能调是因为走服务端转发）。失败时改用「跟随酒馆」，或填一个允许 CORS 的中转/本地地址。
>
> ⚠️ Key 以**明文**存在酒馆设置文件里，客户端扩展没有安全的密钥存储方式，共享设备注意。

### 组件

| 获取最近 N 楼 | 5 | 上下文长度 |
| 回避最新 N 层 | **0** | 组件要读最新内容，所以默认不回避 |
| 使用的 API | 跟随酒馆 | |

### 设定

只有注入总开关和「关键词触发时向前扫描 N 层」。**注入深度在「设定」标签页里逐条设置**。

### 世界书

- **随行发送世界书 / 聊天书条目** — 总开关
- 下方逐条列出所有条目，可单独开关。默认跟随条目在酒馆里的启用状态，你的改动只影响本扩展
- **反控制世界书** — 见下

#### 反控制世界书

把你在这里的勾选状态**写回酒馆世界书本身**（改条目的启用/禁用）。

**为什么需要**：一张角色卡可能有多条平行线 —— 聊天1 走 20 岁线要开 20 岁那组条目，聊天2 走 30 岁线要开 30 岁那组。有了这个，切聊天时不用再手动去世界书里反复开关。

- 状态**按聊天分别保存**
- 开启「切换聊天时自动应用」后，切聊天会自动切换
- **只碰你在本扩展里设定过的条目**，没动过的不管
- 可以整个关掉

### 提示词

可编辑的提示词，改完即时保存：

- **组件生成提示词**
- **表格总则**（各表自己的规则在「表格管理」里）
- **剧情推演 · 生成提示词**
- **剧情推演 · 注入聊天提示词**（支持 `{{event_title}}` `{{branches}}` `{{marker_example}}` 等占位符）
- **总结 · 编排提示词** / **总结 · 压缩提示词**

每段都有「恢复默认」。

> ⚠️ 改注入模板时别删掉 `{{marker_example}}` —— 剧情自动推进就是靠扫描那个标记的。

### 日志

记录每一步：发送的完整提示词、模型返回的完整原文、解析过程、触发判定、注入状态。**只存内存，刷新即清空**，最多 300 条。有「复制全部日志」按钮。

出问题时先看这里。

### 注入总览

列出五个模块当前各注入了多少字符及合计。超 4000 标黄、超 8000 标红。

**注入是会叠加的**，全开可能悄无声息吃掉几千 token。建议常开的只留设定和表格，总结按需开，组件结果一般不用注入。

### 主题

- 跟随酒馆配色 / 自定义 CSS（只作用于本扩展弹窗）
- **组件预览高度上限** — 较矮 40% / 适中 60%（默认）/ 较高 85% / 不限

### 关于 / 更新

- 检查更新、一键从仓库拉取（走酒馆自带的更新接口）
- 「扩展管理器」— 酒馆自带的那个通常更可靠
- 「显示诊断」— 界面显示不出来时点它，会记录窗口几何信息到日志

## 数据存在哪

分两处，都是酒馆自带的存储机制，**不用浏览器缓存**（除了组件折叠状态）。

### 扩展设置（全局，跨聊天共享）

存在 `data/<用户>/settings.json`：

组件定义、表格定义、提示词、剧情发展方向、世界书条目开关、触发方式、注入配置、主题、**API 预设（含 Key）**、**收藏夹**

### 聊天元数据（每个聊天独立）

存在 `data/<用户>/chats/<角色>/<聊天>.jsonl`：

组件生成结果、六张表的数据、剧情矩阵与进度、历史总结、本聊天设定、世界书反控制状态、楼层触发计数

### 关于跨设备

只要连的是**同一个酒馆实例**（比如手机连电脑上跑的酒馆），数据就是共通的 —— 读的是同一份服务端文件。

换一台机器重装酒馆的话不会自动同步，需要手动搬 `settings.json` 和聊天存档。

### 删除与覆盖

- **删除聊天** → 该聊天的数据一并消失，不会残留
- **覆盖**（重新生成组件、更新表格）→ 原数据真的不在了
- **例外**：总结压缩会保留原文，可以还原

## 常见问题

**Q：生成时报 `Failed to fetch`？**
浏览器网络层就失败了，没拿到任何 HTTP 响应。多半是 CORS —— 大多数官方 API 不允许浏览器直连。去「设置 → API 预设」点「测试连接」看具体原因，最快的解法是把该模块的 API 改回「跟随酒馆」。

**Q：总结提示"没有新内容可总结"？**
检查「计数方式」。如果你隐藏了已总结的旧楼层，用「按楼层」模式（默认）就不会有这个问题。

**Q：剧情推演显示的进度不对 / 刚生成就显示某事件结束了？**
每个矩阵会记录生成时的楼层，只认那之后产生的消息。如果仍不对，用顶部「重置进度」。

**Q：打开界面看不见 / 只看到一半？**
去「设置 → 关于」点「显示诊断」，会把窗口几何信息记进日志，把那条发出来。

**Q：组件预览一直变高 / 占满整屏？**
「设置 → 主题 → 组件预览高度上限」调整。超出部分会在预览框内滚动。

**Q：世界书里没勾的条目也被发送了？**
确认「设置 → 世界书」的总开关和逐条开关都对。每次生成会在日志里记录本次「已发送」与「已跳过」的条目清单，可以对照核实。

**Q：检查更新没反应？**
如果不是用 Git 地址安装的（手动解压复制），酒馆侧没有 Git 仓库信息，自动更新用不了。卸载后用仓库地址重装即可。

## 开发

扩展本身**零依赖、无构建步骤** —— `index.js` 就是浏览器实际加载的文件，改完刷新页面即可看到效果。

### 跑测试

```bash
npm install --no-save jsdom jquery   # 首次准备，只用于测试
npm test                             # 105 项
```

测试用 jsdom + 真 jQuery 把扩展整个加载起来，能真实调用内部函数、检查面板渲染。
详见 [`tests/README.md`](tests/README.md)。

> 这个扩展是单文件的，改动多靠字符串替换完成，**替换没匹配上时不会报错**。
> 历史上真因此漏改过默认值、误删过整个函数，所以：**每次改完都跑一遍测试**。

### 发版

```bash
node scripts/sync-version.mjs 3.2.0   # 同步 manifest / index.js / README 的版本号
npm test
```
