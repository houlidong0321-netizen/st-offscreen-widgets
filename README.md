# 镜头之外 · 组件生成器（SillyTavern 扩展）

一个 SillyTavern 第三方扩展：把“想额外生成的小玩意儿”（论坛帖、番外、状态面板……）从正文生成中独立出来，
单独走一条提示词，避免分散模型对正文的注意力；同时提供“镜头之外”功能，专门维护两张状态表
（日程表 / 角色表）并生成镜头外的角色动向、未来事件想象与突发事件清单。

本扩展基于 SillyTavern 官方仓库源码（`SillyTavern/SillyTavern`）的扩展开发文档与实际 API
（`SillyTavern.getContext()`、`extensionsMenu`、`event_types.CHARACTER_MESSAGE_RENDERED`、
`generateRaw`、`setExtensionPrompt`、`getPresetManager` 等）编写，未依赖任何第三方框架。

## 安装

1. 打开 SillyTavern → 左侧「扩展」面板 → 「安装扩展」，粘贴本扩展的 Git 仓库地址；
   或手动把本文件夹整体复制到 `SillyTavern/public/scripts/extensions/third-party/offscreen-widgets/`。
2. 刷新页面。输入框旁的“魔法棒”（扩展菜单）图标里会出现「镜头之外 / 组件生成」入口——
   按你的要求，**没有**在顶部扩展面板里额外放置入口。

## 功能对照

### 组件（Widgets）—— 现在拆成两个模块
- **模块① 组件显示**：所有已生成结果集中显示在面板最上方，每个都是独立的
  `<iframe sandbox="allow-scripts">` 渲染预览卡片，带「查看源码」「重新生成」按钮。
- **模块② 组件列表**：在下方，只负责“新建/编辑名称与提示词/勾选预设条目/开关/删除”，
  不再和结果混在一起。单独生成某个组件后，结果会出现在上面的模块①里。

- 「组件生成」面板：新建组件（名称 + 提示词），逐个开关是否随批量生成一起发送。
- 每个组件卡片里可以选择酒馆当前的 **Chat Completion 预设**，读取该预设下的所有条目（Prompt Manager
  条目），勾选后加入组件的附加参考素材。
- 触发模式（设置页）：
  - **手动**：点「立即生成全部已开启组件」或单个组件的播放按钮。
  - **自动**：监听 `CHARACTER_MESSAGE_RENDERED` 事件，检测新一条 AI 回复中是否出现完整闭合的
    `<content>...</content>` 标签，出现即自动跑一遍生成。
- 发送时**不套用酒馆当前预设**，而是用扩展内置的框架系统提示词（强调“仅供把玩、不进入正文、
  但需符合人设与世界观、允许自行用 HTML/内联 CSS 美化”），拼接组件自身提示词 + 勾选的预设条目
  + （可选）最近 N 条聊天记录 + （可选）世界书 / 角色卡内嵌世界书全文。
- 结果以 `<iframe sandbox="allow-scripts">` 方式渲染在组件卡片下方，可直接预览排版效果，也可以
  「查看源码」在新标签页看原始 HTML。
- 设置页可选择是否在**下一次生成正文时**把组件结果注入进去，以及注入位置（提示词顶部 /
  按深度插入聊天记录中 / 提示词最前）与深度，默认关闭。
- **组件系统提示词现在带有最高优先级指令**：很多酒馆预设自带的小组件条目会附带固定输出格式规范
  （给正文用的排版/标签体系/字数限制等），这些格式规定会被明确要求忽略——模型只提取其中的
  设定/人设/世界观信息作为参考，最终 HTML 的排版与美化方式完全自主决定，不再套用预设原有格式。
- 每个渲染结果的预览框右上角新增一个「⛶ 全屏」按钮，点击后用浏览器原生全屏 API 把该组件的
  渲染内容放大到整个屏幕沉浸式查看，按 Esc 退出。

### 镜头之外（六张可编辑表格）
- 全部为结构化表格，标题不带“表X”编号，只保留表名：
  - **日程表**：角色 / 固定日程规律 / 时节性必然事件 / 弹性事务参考池
  - **角色表**：姓名 / 昵称 / 与用户的关系 / 当前位置与正在做的事 / 对用户的态度
  - **场景表**：标签 / 场景名称 / 地理位置·距离参照 / 建筑·环境构造细节 / 用途
  - **物品轨迹表**：标签 / 物品名称 / 关联章节 / 当前位置 / 状态
  - **核心待办事项表**：时间 / 事项 / 关联章节
  - **伏笔表**：标签 / 内容 / 埋设章节 / 状态
- 提示词里已写入你要求的规则体系，重点包括：
  - **“正文触发原则”只约束场景表与物品轨迹表**——正文没写就原样保留旧数据，禁止靠推理主动改动；
  - **角色表明确不受该原则约束**，可以描写不在场角色此刻的状态；
  - **各表生命周期彼此独立**，不共用同一套清理标准（场景表有 10 章失活清理、伏笔表回收后下轮删除、
    待办事项表一旦开始发生即整行删除、物品轨迹表按纪念/杠杆两类分别判定终态）；
  - 所有编号标签输出时都带反引号，如 `` `[Scene_1]` ``。
- 每次生成都会把已有六张表一并发回给模型，要求按各表规则增量更新而不是推倒重写。
- 每个单元格可直接点击编辑（`contenteditable`），每张表下方都有“+ 添加一行”。
- 同样可在设置页选择是否注入正文、注入位置与深度，默认关闭。
- 旧版本存档（含 narrative 字段、或只有旧的两/四张表）会被自动兼容读取，不会报错；缺失的新表以空表出现，
  可手动补充或重新生成一次。

### 世界书（独立标签页）
- 自动识别三类来源并合并去重：酒馆世界书面板里**当前勾选激活的全局世界书**、**当前角色绑定的主世界书**、
  **当前聊天绑定的聊天书**。
- 列出这些书里的**每一条条目**，每条前面有独立开关，决定它是否在生成组件/镜头之外时随行发送。
- 默认状态跟随该条目在酒馆里的启用/禁用状态；你的手动改动只保存在本扩展内，**不会修改酒馆世界书本身**。
- 顶部有“拉取/刷新条目列表”与“全部恢复默认”两个按钮。
- 注意：这些开关只有在设置页勾选了“随行发送世界书/聊天书条目”后才实际生效。

### 提示词（独立标签页）
- 把实际发送给模型的两段系统提示词原文摊开成可编辑文本框，改完即时保存生效，
  以后微调措辞不用再去动扩展代码：
  - **组件生成提示词**（含“最高优先级忽略预设固定格式”那段指令）
  - **镜头之外 / 表格生成提示词**（含六张表的完整规则与 JSON 输出格式约定）
- 每段都有“恢复默认”按钮，可随时回退到扩展内置的默认文本。
- ⚠️ 如果你要改表格提示词，注意不要破坏末尾那段 JSON 结构说明（`schedule_table` / `character_table` /
  `scene_table` / `item_anchor_table` / `timeline_table` / `foreshadow_table` 六个键名），
  扩展是靠这些键名把返回结果填进对应表格的，键名改了就会解析不出内容。

### 设置页
- **触发方式**：手动，或自动。自动模式下有三个可同时开启、互不冲突的子触发器：
  - 检测到新回复中出现完整 `<content>…</content>` 闭合标签时触发（组件与镜头之外一起生成）；
  - **组件每 N 楼层自动生成一次**；
  - **镜头之外每 M 楼层自动生成一次**（需先在“镜头之外”标签页启用该功能）。
  “楼层”按当前聊天总消息条数计算，两个楼层计数各自独立记录在当前聊天的存档里；标签触发命中的那一轮
  会把两个计数对齐到当前楼层，避免紧接着又因楼层到量而重复生成。
- 随行聊天记录条数、是否携带世界书条目 / 角色卡内嵌世界书全文。
- 组件与镜头之外的正文注入开关、位置、深度（各自独立）。
- **关于 / 更新**：见下方“更新提醒”。
- **API**：默认“跟随酒馆当前 API”（通过 `generateRaw` 走酒馆当前选择的连接配置，不经过世界书/作者注释
  自动扫描，所有上下文由本扩展自行拼接）；也可切换到“独立 API”，填写 URL / Key / 模型名即**自动保存**
  （已取消“确认保存”按钮，输入即写入设置，不会再出现因忘记点保存导致下一次请求带着旧值触发 400 的情况），
  「拉取模型列表」会请求 `${url}/models`（OpenAI 兼容格式）。
- **主题**：默认跟随酒馆系统配色（CSS 变量），也可以在文本框里写自定义 CSS 并保存——
  为避免污染酒馆全局样式，样式只会被注入到本扩展的弹窗内，建议使用 `.ow-` 前缀的选择器覆盖
  （具体类名见 `style.css`）。

### 日志诊断（新增）
- 主界面新增「日志」标签页，记录了每一步关键动作：
  - `trigger`：自动模式下每条新回复是否命中 `<content>...</content>` 检测；
  - `request`：发给模型的完整 system/user 提示词（组件与镜头之外分别标注）；
  - `response`：模型返回的**完整原始文本**（未截断），响应为空也会有警告日志；
  - `parse`：「镜头之外」JSON 解析过程——依次尝试直接解析/去代码块围栏/截取花括号片段，
    每一步成功或失败都会记录，最终失败会给出明确提示；
  - `inject` / `system` / `ui`：注入状态变化、生成流程开始结束、界面操作等。
- 日志只保存在当前页面会话内存中（最多 300 条，刷新页面会清空），点击「复制全部日志」
  可以把完整日志复制到剪贴板，方便你直接贴给开发者对照排查“到底发到哪了、模型返回了什么、
  为什么没解析出表格”。
- 之前版本里「镜头之外」生成失败会被 `try/catch` 悄悄吞掉、界面上什么提示都没有——这是导致
  “识别不出来两个表格”的主要原因之一。现在失败会有 toast 提示 + 完整日志，且 JSON 解析改为
  多种兜底策略（直接解析 → 去 Markdown 围栏 → 截取花括号片段 → 兼容中文/拼音字段名），
  仍然失败时日志会明确写出“模型没有按 JSON 格式返回”，可以直接对照 `response` 日志里的原始
  文本判断具体是模型没听指令，还是返回被截断，或者所选 API/连接根本没有正常返回内容。

### 更新提醒（Git 仓库分发）
- 本扩展通过 Git 仓库分发：`https://github.com/houlidong0321-netizen/st-offscreen-widgets`
- 打开扩展时会自动静默检查一次更新（复用酒馆自带的 `/api/extensions/version` 接口，没有自建服务）。
- 有新版本时：输入框旁菜单入口会出现 `NEW` 角标，弹窗内标签栏下方会出现一条蓝色横幅，
  点“立即更新”即可**直接从原仓库拉取更新**（走酒馆自带的 `/api/extensions/update`），
  完成后会提示刷新页面生效。设置页“关于 / 更新”里也有手动“检查更新”按钮与当前提交号。
- 扩展目录名通过 `import.meta.url` 自动识别（酒馆以 ES module 方式加载扩展入口，
  `document.currentScript` 在这种情况下恒为 `null`，不能用来定位自身路径）。
  若你把安装目录改名成了非 `st-offscreen-widgets` 的名字，自动识别仍然有效；
  只有在极特殊情况下识别失败时，才需要去代码顶部改那个回退值。
- 如果不是用 Git 地址安装的（比如手动解压复制），酒馆侧没有 Git 仓库信息，
  自动更新会失败并在状态区给出说明，此时请手动覆盖文件或改用仓库地址重装。

## 已知限制 / 后续可自行调整的点

- **预设条目读取**目前基于 Chat Completion（OpenAI 兼容）类 API 的 Prompt Manager 结构
  （`getPresetManager('openai')` → `preset.prompts[]`）。如果你主力用 Text Completion / KoboldAI
  等后端，预设下拉列表会读取不到条目，这是酒馆本身预设结构的差异，非 bug。
- **API Key 明文存储**：SillyTavern 官方文档明确说明客户端扩展没有安全的密钥存储方式，独立 API 的
  Key 会以明文保存在酒馆设置文件/浏览器本地存储中，请自行评估风险，不要在公共/共享环境中使用敏感 Key。
- **世界书发送的是全文，不做关键词触发筛选**：勾选发送的条目会被整条塞进请求里，而不是像酒馆正文那样
  按关键词命中才注入。条目多时 token 消耗会明显上升，建议去“世界书”标签页只勾选真正需要的条目。
- **全局激活世界书的识别方式**：酒馆没有通过 `getContext()` 暴露“当前激活的全局世界书”列表，
  因此这部分是读取世界书面板的 `#world_info` 多选框取值。如果未来酒馆改了这个元素的 id，
  全局书可能识别不到（角色绑定书与聊天书走的是 `getContext()`，不受影响）。此时可在
  `getBoundWorldInfoBookNames()` 里调整选择器。
- 标签自动触发的正则是 `/<content>[\s\S]*?<\/content>/i`，如果你的正文闭合标签写法不同，请到
  `index.js` 里 `messageHasClosedContentTag` 函数自行调整。
- **楼层触发按消息总条数计算**，包含用户消息在内。如果你希望只按 AI 回复计数，可在
  `onCharacterMessageRendered` 里把 `c.chat.length` 换成过滤后的条数。
- 存储位置分两处：生成结果、六张表数据、楼层触发计数存在**当前聊天的存档元数据**里（随存档走，
  换聊天不共享）；组件定义、触发方式、提示词、世界书条目开关等存在**扩展设置**里（全局共享）。
- **提示词自定义后不会被版本更新覆盖**：设置合并采用“已有值优先”策略，扩展更新后你改过的提示词仍保留。
  反过来说，如果某次更新改进了默认提示词，你需要手动点“恢复默认”才能用上新版措辞。
